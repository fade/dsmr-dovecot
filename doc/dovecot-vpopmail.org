* TL;DR
:PROPERTIES:
:DESCRIPTION: A configuration-only package that makes dovecot 2.4 serve vpopmail users.
:END:

=dovecot-vpopmail= is a *configuration-only* package (=Architecture: all=, no
compiled code). It wires stock dovecot 2.4 to the DSMR qmail/vpopmail stack:
IMAP users authenticate against the *vpopmail PostgreSQL* database and read their
qmail-delivered Maildirs, with all connections requiring TLS.

Dovecot 2.4 removed the =vpopmail= and =checkpassword= passdb drivers that 2.3
shipped; the only supported path to vpopmail accounts is now dovecot's native
*SQL passdb* driver querying the database directly. This package encodes that
integration — five =conf.d= snippets plus a postinst that generates the
PostgreSQL connection block, the TLS certificate, and the system-user fallback
file.

This manual documents *what the packaging configures and why*. It is not a
re-derivation of upstream dovecot documentation (=doveadm(1)= and the dovecot
manuals cover the daemon itself).

* Theory of operation
:PROPERTIES:
:DESCRIPTION: The auth chain, the conf.d snippets, and the postinst.
:END:

** Authentication chain
1. An IMAP client connects on 993 (implicit TLS) or 143 (STARTTLS) and sends
   =LOGIN user@domain password= over TLS.
2. =05-vpopmail-auth.conf= loads before =10-auth.conf=, so the SQL passdb is
   tried first.
3. dovecot runs the password query against the =vpopmail= table and verifies the
   returned =$6$= hash with =default_password_scheme = SHA512-CRYPT=.
4. The userdb query returns =pw_dir= as home and uid/gid =89= (=vpopmail:vchkpw=).
5. dovecot opens =<pw_dir>/Maildir/= as the INBOX.
6. If the user is *not* in the vpopmail table, the chain continues
   (=result_failure = continue=) to a =passwd-file= passdb reading
   =/etc/dovecot/system-passwd=, so curated Unix users can read mail too.

The same =system-passwd= file is the SMTP-AUTH allow-list managed by
*dsmr-smtpauth(8)* — IMAP and submission share one source of truth.

** The conf.d snippets
| File                         | Load order | Purpose                               |
|------------------------------+------------+---------------------------------------|
| =05-vpopmail-auth.conf=      | before 10  | auth mechanisms; include the SQL ext  |
| =vpopmail-auth-sql.conf.ext= | via 05     | passdb/userdb: SQL then system-passwd |
| =99-vpopmail-mail.conf=      | after all  | Maildir layout, uid/gid, INBOX path   |
| =99-vpopmail-master.conf=    | after all  | auth socket ownership/permissions     |
| =99-vpopmail-ssl.conf=       | after all  | =ssl = required=                      |

** INBOX / Maildir compatibility
Dovecot 2.4 defaults to storing INBOX at =<mail_path>/.INBOX/=, which does not
match qmail/=vdelivermail=, which delivers to =<pw_dir>/Maildir/new/=.
=99-vpopmail-mail.conf= sets =mail_inbox_path = ~/Maildir= so dovecot's INBOX
*is* the Maildir root — the single most important line for "mail delivered but
IMAP shows an empty inbox".

** What the postinst generates (not conffiles)
| File                                         | Owner/Mode       | Source                                   |
|----------------------------------------------+------------------+------------------------------------------|
| =/etc/dovecot/dovecot-vpopmail-sql.conf.ext= | root:dovecot 640 | from =/home/vpopmail/etc/vpopmail.pgsql= |
| =/etc/dovecot/system-passwd=                 | root:dovecot 640 | created empty if absent                  |
| =/etc/dovecot/private/dovecot.pem=           | root:dovecot 644 | extracted from qmail cert                |
| =/etc/dovecot/private/dovecot.key=           | root:dovecot 600 | extracted from qmail cert                |

The postinst reads the pipe-delimited =host|port|user|password|database= from
=/home/vpopmail/etc/vpopmail.pgsql=, writes the dovecot 2.4 =pgsql= connection
block, extracts the TLS cert+key from =/etc/qmail/servercert.pem= (or self-signs
if absent), ensures =system-passwd= exists, and runs =doveadm reload=. It is
idempotent: TLS is only generated when the cert is missing.

* Usage
:PROPERTIES:
:DESCRIPTION: Install order, service control, and verifying logins.
:END:

Install after the dovecot packages and vpopmail (whose database must exist):

: # apt install dovecot-core dovecot-imapd dovecot-pgsql vpopmail
: # dpkg -i dovecot-vpopmail_*.deb

Service control and a soft reload that does not drop sessions:

: # systemctl restart dovecot
: # doveadm reload

Verify a login and the userdb resolution:

: # doveadm auth test user@example.com
: # doveadm user user@example.com           # shows uid/gid/home/mail_path
: # openssl s_client -connect localhost:993 -quiet   # then: a LOGIN user@example.com pw

Inspect the generated SQL block and test the query path:

: # cat /etc/dovecot/dovecot-vpopmail-sql.conf.ext
: # psql -U vpopmail -c "SELECT pw_name,pw_domain,pw_dir FROM vpopmail LIMIT 5;"

* Configuration
:PROPERTIES:
:DESCRIPTION: Editing the snippets, regenerating SQL, replacing the cert.
:END:

- *The conffiles* live in =/etc/dovecot/conf.d/= and are the editable policy
  surface (auth mechanisms, Maildir layout, =ssl = required=). Reload dovecot
  after edits.
- *Regenerate the SQL connection block* after rotating the database password
  (i.e. after =/home/vpopmail/etc/vpopmail.pgsql= changes): remove
  =/etc/dovecot/dovecot-vpopmail-sql.conf.ext= and =dpkg-reconfigure
  dovecot-vpopmail=, then =doveadm reload=.
- *Replace the TLS certificate* by removing =/etc/dovecot/private/dovecot.pem=
  and =.key= and re-running the postinst (=dpkg-reconfigure=), or re-extracting
  from =/etc/qmail/servercert.pem= by hand.

* Extension points
:PROPERTIES:
:DESCRIPTION: Adding system users; chaining further passdbs.
:END:

- *Authorise a Unix user for IMAP.* Add a =user:{CRYPT}$6$…:uid:gid::home:shell=
  row to =/etc/dovecot/system-passwd= (the *dsmr-smtpauth(8)* =add= subcommand
  does this and verifies it), and route the address to that user in qmail's
  =users/assign= with an exact-match entry. The user then reads mail over IMAP
  *and* may SMTP-AUTH, from one file.
- *Chain another passdb.* Any additional =passdb { }= with
  =result_failure = continue= extends who can authenticate without touching the
  vpopmail or system-passwd stages.

* Gotchas and debugging
:PROPERTIES:
:DESCRIPTION: The 2.4 pgsql format, INBOX path, and credential order.
:END:

- *Dovecot 2.4 pgsql syntax is not 2.3's.* In 2.4 the host is the *section
  label* and the credentials live in a =parameters { }= sub-block; the
  =libdriver_pgsql.so= driver rejects the old flat form at runtime. The postinst
  emits the 2.4 form — if you hand-edit the connection file, match it.
- *Mail delivered but IMAP inbox empty.* Almost always the INBOX path: confirm
  =mail_inbox_path = ~/Maildir= is in effect (=doveadm user= shows =mail_path=),
  not dovecot's 2.4 default =~/Maildir/.INBOX/=.
- *=vpopmail.pgsql= field order.* The canonical order is
  =host|port|user|password|database=; a swapped password/database pair makes
  auth fail with a connection error. =dsmr-email-admin fix pgsql-config= repairs
  the common reversal.
- *System-passwd needs the ={CRYPT}= prefix.* dovecot's passwd-file passdb does
  not auto-detect crypt hashes; an entry without ={CRYPT}= silently never
  matches. =auth_username_format = %{user|username}= strips the domain, so a row
  keyed by the bare name serves both =marvin= and =marvin@example.com=.
- *All IMAP requires TLS.* =ssl = required= means a plaintext :143 login without
  STARTTLS is refused by design; use 993 or STARTTLS on 143.
